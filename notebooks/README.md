# 📓 Ноутбуки Kaggle + Colab — anime_upscale

Готовые runner-ноутбуки: предпусковая проверка среды (fail-fast, русский вердикт), bootstrap
клона + `uv`, сборка misc-плагина, скачивание моделей по манифесту, запуск пайплайна и выгрузка
результата на gofile. Пресет кодирования — **`medium` везде** (решение владельца): честная математика
времени печатается баннером ячейки 1 — на 2–4 vCPU ожидайте ≈ 1.5–4 fps кодирования @1080p.

| Файл | Платформа | Особенности |
| :-- | :-- | :-- |
| `kaggle_run.ipynb` | Kaggle Notebooks (GPU T4 x2) | cu130 из lock (драйвер 580), защитная ветка cu126 при CUDA < 13 |
| `colab_run.ipynb` | Google Colab (GPU T4) | обязательный проб драйвера → **cu126 + пины `<2.15`**, лестница деградации TensorRT, Drive-ячейки |

## ✅ Пререквизиты

**Kaggle**
- Аккаунт с **подтверждённым телефоном** (phone-verified) — без него недоступны GPU-ускоритель и
  переключатель Internet.
- В настройках сессии ноутбука: `Accelerator → GPU T4 x2`, `Internet → ON`.
- Недельная GPU-квота ≈ 30 часов (разделяемая; точное значение Kaggle не публикует).

**Google Colab**
- Любой аккаунт Google; в `Runtime → Change runtime type` выбрать `T4 GPU`.
- Free-tier сессия ограничена по использованию (~5 ч типично), может обрываться без предупреждения.

**Репозиторий.** Ячейки клонируют публичный `https://github.com/4q4r/anime_upscale.git` (константа
`REPO_URL` в ячейке 1) — анонимный `git clone` работает без credentials (в ячейках их нет by design).
Если доступность репозитория изменится — подставьте свой публичный форк в `REPO_URL`.

## 🟢 Kaggle — пошагово

1. **Создайте ноутбук**: kaggle.com → Create → Notebook → File → Import Notebook → загрузите
   `kaggle_run.ipynb` (метаданные файла включают T4 и Internet — проверьте их в Settings).
2. **Ячейка 1 (setup)** — пробует среду (GPU / интернет / git / g++ / curl / ffmpeg + libx265 / диск)
   и печатает русский баннер; любая проблема = громкий вердикт с подсказкой и стоп. Затем: клон репо
   в `/kaggle/working/anime_upscale` (существующий клон переиспользуется = resume), установка uv,
   `uv sync`, проба TensorRT, сборка misc-плагина (SCDetect), `models fetch`.
3. **Ячейка 2 (запуск)** — замените `xxxx` на код своей ссылки gofile и запустите:
   `!cd /kaggle/working/anime_upscale && uv run anime-pipeline --profile interp-only --upload -i https://gofile.io/d/xxxx`
   Варианты `-i`: ссылка gofile (папки разворачиваются в батч), имя файла из `input/`
   (см. рецепт Datasets ниже), повторяемый `-i` = батч.
4. **Ячейка 3 (результаты)** — листинг `output/`, напоминание про gofile-ссылки (печатаются в выводе
   ячейки 2) и честная оценка бюджета сессии по факту прогона.

Для нечеловеческих прогонов используйте **Save & Run All (Commit)**: ноутбук исполняется сверху вниз
без участия пользователя в рамках 12-часовой сессии; результаты сохраняются в версии ноутбука
(вкладка Output, квота `/kaggle/working` ≈ 20 ГБ).

## 🟡 Google Colab — пошагово

1. colab.research.google.com → Upload → загрузите `colab_run.ipynb` → `Runtime → Change runtime type → T4 GPU`.
2. **Ячейка 1 (setup)** — как на Kaggle, плюс **обязательный проб драйвера**: на Colab драйвер
   550-класса (CUDA 12.x), поэтому ячейка сама переводит torch на индекс **cu126** с пинами
   `torch<2.15` / `torch-tensorrt<2.15` (cu130-сборка на этом драйвере не запустится; cu126-колёса
   не публикуются с torch 2.15 — пины обязательны). Правки эфемерны, живут только в клоне.
3. **Ячейка 2 (опционально)** — монтирование Google Drive (`MOUNT_DRIVE = True`; появится штатное
   окно авторизации Google). Без Drive всё живёт в `/content` и пропадает с сессией.
4. **Ячейка 3 (запуск)** — как на Kaggle, cwd `/content/anime_upscale`.
5. **Ячейка 4 (результаты)** — листинг и бюджет сессии.
6. **Ячейка 5** — копирование `output/*.mkv` в `MyDrive/anime_upscale_output/` (требует смонтированный Drive).

| :-- | :-- | :-- |

## 🧮 Бюджет сессии (честная математика)

Профиль `interp-only` = интерполяция RIFE до 60 fps + кодирование x265 10-bit `preset medium`.

```
серия ~24 мин @ 23.976 fps → ≈ 34.5 тыс. кадров источника
интерполяция до 60 fps      → 86 400 кадров результата (24 мин × 60 fps; ≈2.5× к источнику; GPU T4: минуты)
кодирование medium @1080p   → ≈ 1.5–4 fps на 2–4 vCPU → 6–16 ч ТОЛЬКО на кодирование (86 400 / [4…1.5] fps)
```

Выводы:
- **По одной серии на сессию.** Обрыв сессии теряет недокодированный файл — продолжения с середины
  нет.
- Даже оптимистичный сценарий (6 ч) превышает типичную ~5-часовую Colab-сессию — на Colab серия
  фактически двухсессионная. Интерполяция на T4 быстрая; узкое место — CPU-кодирование. Снизьте
  `--target-fps 30` или
  `24000/1001`, чтобы сократить число кадров, либо кодируйте на своей машине.
- Ячейка результатов после прогона печатает эту же оценку по фактической длительности результата
  (ffprobe): «серия такого объёма ≈ X–Y ч кодирования».

## 📥 Вход через Kaggle Datasets (рецепт симлинка)

Основной путь входа — ссылки gofile. Локальные файлы: загрузите их как Kaggle Dataset, прикрепите
к ноутбуку (Add Input → Datasets) — датасет появится по пути `/kaggle/input/<slug>/` (read-only) —
и подсуньте симлинком в `input/` клона (в ячейке запуска или отдельной ячейкой):

```bash
!mkdir -p /kaggle/working/anime_upscale/input
!ln -sf /kaggle/input/<slug>/<файл>.mkv /kaggle/working/anime_upscale/input/<файл>.mkv
```

После этого `-i <файл>.mkv` (имя из `input/`). На Colab то же самое с файлами из Drive:
`!ln -sf /content/drive/MyDrive/anime_upscale_input/<файл>.mkv /content/anime_upscale/input/<файл>.mkv`.

## 🔻 TensorRT: деградация

Лестница (план §2.2):
1. **TRT on** — T4 (sm_75) поддерживается TensorRT 10.x; на Kaggle это дефолт.
2. **TRT off → PyTorch CUDA FP16 (`rgbh`)** — если `torch-tensorrt` не разрешился для связки
   Python/CUDA (правда Colab с cu126) ячейка setup сама уберёт зависимость и выставит
   `[stages.interpolate] trt = false` в config.toml **клона** (эфемерно, репозиторий не меняется).
3. Если прогон упал на сборке TRT-движка (движок собирается лениво при первом запуске) — выставьте
   `SEED_TRT_OFF = True` в ячейке 1 и перезапустите её: та же деградация принудительно.

## 🔒 Фиксированные решения

- **Пресет `medium` везде** — никакого notebook/fast профиля; время печатается честной математикой.
- **Гостевой токен gofile живёт пер-сессию.** Ключ `state_file` в конфиг НЕ добавлялся: `$HOME`
  на обеих платформах эфемерный, токен создаётся заново каждую сессию (частая регенерация
  тарифицируется gofile рейтинг-лимитами — норма для разовых прогонов).
- **Вход — gofile-ссылки primarily**; Datasets/Drive — рецепт симлинка выше.
- **Никаких интерактивных промптов и credentials в ячейках**; докеризация не используется (Colab ToS).
- Конфиг приложения не читает переменные окружения; все адаптации — пробы и правки внутри ячеек
  (эфемерные мутации клона).

## 🧪 Идемпотентность и dry-run

- Ячейки идемпотентны: повторный запуск ячейки 1 переиспользует клон (fetch + reset до `origin/HEAD`:
  локальные правки кода сбрасываются — `config.toml` правьте ПОСЛЕ ячейки 1), `uv sync` докатывает
  недостающее, misc-плагин пересобирается.
- `ANIME_NOTEBOOK_DRY=1` — сухой прогон python-ячеек без сети и мутаций (пробы печатают вердикты,
  шаги печатают `[DRY]` и пропускаются).
- `ANIME_NOTEBOOK_WORKROOT=/путь` — переопределение рабочего каталога для локального e2e-теста
  ячейки (используется при валидации ноутбуков; на платформах не задаётся).
- JSON-валидность и структура ноутбуков проверяются при сборке (`nbformat`-структура + ast-парс
  кодоячеек); живой прогон на Kaggle/Colab — шаг приёмки владельца.
