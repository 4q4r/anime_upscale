# Производительность и питание

Как пайплайн защищает заявленную скорость длинных батчей от «спятившей» или
экономной ОС (волна P1 анти-троттлинг-защиты; план —
`/tmp/opencode/anime_upscale-impl/plan-power-throttling.md`).

## Что пайплайн делает сам (уже встроено)

| Механизм | Что делает | Где проверить |
| :-- | :-- | :-- |
| Keep-awake | На время батча процесс сообщает ОС «не спать»: Windows — `SetThreadExecutionState(ES_CONTINUOUS \| ES_SYSTEM_REQUIRED)` (дисплей может гаснуть, удерживается только системный idle-таймер — CPU/GPU-активность его НЕ сбрасывает). Снятие — гарантированно при любом завершении, включая Ctrl+C. Fan-out-воркеры держат свой запрос каждый. | `powercfg /requests` |
| EcoQoS opt-out | Процесс один раз на запуск явно отказывается от эвристик экономии (Windows: `SetProcessInformation(ProcessPowerThrottling)` с `ControlMask=EXECUTION_SPEED, StateMask=0` — документированный Microsoft «HighQoS»-паттерн): ОС не классифицирует батч как фоновый/эффективный режим. | Диспетчер задач → колонка статуса power throttling / «Режим эффективности» |
| Startup-доктор | Только чтение и только предупреждения при старте: активный план питания по GUID (сравнение локале-независимое; Balanced = рекомендация Microsoft для Server — одна мягкая заметка, не брань), питание от батареи (Windows); governor `powersave` на legacy cpufreq-драйвере (Linux). Ничего в системе не меняет, ничего не блокирует. | строки ⚠/⏭ рядом с баннером оборудования |
| RateWatch | Детектор просадки скорости: скользящие окна по 5 с, первые 2 — прогрев, базлайн = медиана окон 3–6 этапа; два окна подряд ниже 60% базлайна → один громкий ⚠ «похоже на троттлинг/сон» с готовыми командами проверки. Питается скоростью самого прогресс-бара (без повторного замера); у каждой серии — свой базлайн. | ⚠ в прогрессе серии |

Что остаётся на пользователе: подключить питание (ноутбук — Windows на батарее
может троттлить фоновые процессы и обрывать keep-awake). На Linux гарантия от
засыпания хоста — обёртка запуска (изнутри процесса inhibitor недоступен):

```bash
systemd-inhibit --who=anime_upscale --why="батч" anime-pipeline --profile full -i серия1.mkv
```

## Почему в диспетчере задач GPU «спайкует» 0–100% (placeholder)

Пайплайн чередует CPU-фазы (decode, VS-фильтры, libx265) и GPU-фазы
(upscale/RIFE), а Task Manager по умолчанию показывает не все движки (Compute
не входит в дефолтную четвёрку) — часть «спайков» = артефакт измерения.
Истинная телеметрия: наш прогресс-бар (кадр/с) и `nvidia-smi`.
